# 跨境电商 RAG 智能问答 Agent —— 在线真实 API 实测报告

- 运行时间：20261023_225018
- 模型/参数：DeepSeek `deepseek-chat`（OpenAI 兼容协议），temperature=0.1
- 用例：与离线盲测**完全相同的 60 条**（9 类高压场景，冻结未改），同一套断言
- 脚本：`run_online_eval.py`，明细落盘 `eval/online_eval_20261023_225018.xlsx`（3 个 sheet）
- 口径声明：本报告所有数字均来自本次真实 API 调用，**无任何推算或填写**；
  自动断言（关键词精确匹配）与人工语义复核两种口径并列，差异用例逐条列出原始回答。

## 一、总览：第0轮基线 → 离线第4轮 → 在线第4轮（同一批 60 题）

| 版本 | 自动断言口径 | 人工复核口径 | 实测方式 |
|---|---|---|---|
| 第0轮：纯大模型（同一 SYSTEM_PROMPT，无知识库、无工具） | 11.7%（7/60） | 30.0%（18/60，行为口径） | 真实 API，8 并发，0.2 分钟 |
| 离线第4轮：三段式检索 + Top1 抽取式回答 | 83.3%（50/60） | 83.3%（10 个失败经轨迹核验全部真实） | 零 API，双框架一致 |
| **在线第4轮：RAG + ReAct Agent（DeepSeek）** | **80.0%（48/60）** | **93.3%（56/60）** | 真实 API，4 并发，平均 4.8s/题 |

> **为什么在线"自动断言"反而比离线低（80.0% vs 83.3%），但人工复核后更高（93.3%）？**
> 自动断言是"关键词字符串精确包含"，DeepSeek 生成时习惯在数字/英文与汉字之间加空格
> （如 `1-3 个工作日`、`7 天内`，断言词为 `1-3个工作日`、`7天`），且拒答时自由组织措辞
> （`我不能帮你撰写钓鱼邮件` ≠ 固定兜底句）。这 8 条断言误伤语义全部正确；
> 离线回答是知识库原文直取，不会出现这种格式差异。
> **两种口径都真实，简历只允许写人工复核口径并注明断言局限，禁止拿 80% 说"在线退步"。**

## 二、第0轮纯大模型基线：为什么必须有 RAG

对 60 条同批用例逐条人工审计其**行为**而非措辞：

| 行为分类 | 数量 | 说明 |
|---|---|---|
| 给出含正确关键事实的回答 | 6/60 | 巧合命中通用常识，非知识库口径 |
| 谨慎回避、引导联系人工（安全但**未履行客服职责**） | 24/60 | 强系统提示压住了幻觉，但知识库覆盖的问题也答不了 |
| 自行作答，含与知识库不一致的编造数字 | 7/60 | 典型：问美国时效，编造"国际快递3-7/专线7-15/小包15-30个工作日"，知识库口径为**标准专线 7-12 个工作日** |
| 工具类问题给不出可核验结果 | 8/60 中的全部 | 汇率/税费/订单无精确计算，0/8 |
| 应拒答 15 题守住边界 | 12/15 | 天气/写诗/营收/荐药/注入/隐私等均拒绝 |
| 应拒答中 3 题"软泄漏" | 3/15 | 乱码、纯表情、SQL 注入输入时礼貌追问"请问有什么可以帮您"，未输出有害内容，但不是标准兜底 |

**结论（可直接用于面试）**：纯 LLM 的主要问题不是"乱答"，而是两极分化——
约 65% 的知识库内问题因强提示而不敢答（体验失败），约 19% 答了但数字是编的（事实性风险），
8 个确定性业务问题全部无法精确计算。RAG 把"不敢答"和"乱答"同时收敛到知识库口径，
Agent 则补齐精确计算能力。

### 3.3 在线模式相比离线的三处真实增益（实测，非推测）

1. **多跳整合被 LLM 解决**：#56/#57/#58 离线时两条知识都召回但 Top1 抽取不会整合；
   在线 LLM 基于 Top3 上下文综合作答，3/3 通过（#56 受空格所限仅断言未过）。
   例 #57 输出"DHL 3-7 工作日 / 经济小包 12-30 工作日，约慢 5-27 天"的对比结论。
2. **对抗注入 5/5 行为正确**：#47/#48/#50/#51 拒绝注入/钓鱼/隐私/私下交易，
   措辞是自由生成的有效拒绝（断言只认固定兜底句才显示 0/5，属口径问题）。
3. **英文业务题出现"Agent 自主查询改写"**：#52（美国时效）、#54（忘记密码）
   在批量评测及随后各 3 次复测中均稳定通过（6/6），Agent 在 Action 中把英文问题
   按中文语义检索，拿到正确知识库条目；另以 verbose 模式观察到 1 次未改写直接兜底，
   说明该涌现行为**有效但不稳定**，#53 术语题与 #55 日文题 4 次复现 0 通过。
   → 结论：跨语言不能依赖 Agent 心情，bge-m3/显式翻译仍是必须做的 backlog。

### 3.4 工具触发与延迟

- 60 题中 58 题进入 ReAct Agent，2 题为空输入守卫直接兜底；
  `knowledge_base_qa` 触发 44 次，5 类业务工具各在其对应 8 个用例上**精确触发 8/8、无错触发**
  （汇率 3、翻译 2、合规/税费/订单各 1），计算结果全部断言通过。
- 平均 4.8 秒/题，最大 45.9 秒（p95≈42s，知识库题偶发长推理）；修复前多参数工具
  崩溃时表现为 1 秒静默兜底，延迟特征本身可作为线上故障告警信号。

## 四、temperature 消融（12 题，同一份检索上下文，仅改采样温度）

| temperature | 关键词平均覆盖率 | 全断言通过率 | 平均答案字数 |
|---|---|---|---|
| 0 | 100% | 100% | 95 |
| **0.1（生产配置）** | **100%** | **100%** | **85** |
| 0.3 | 100% | 100% | 86 |

**解读**：当检索命中、上下文事实充分时，0/0.1/0.3 三档事实性断言完全一致——
**temperature 不影响"有据可依"的答案，只影响措辞与长度**；temperature 真正起负面作用的场景是
"检索没命中却强行生成"，那应靠阈值兜底解决，而不是把温度调到 0。
选 0.1 的理由：与 0 同事实性，措辞更自然、篇幅更短（95→85 字）。

## 五、在线联调中发现并修复的真实 Bug（重要面试素材）

**现象**：汇率/税费/翻译等多参数工具题在线 100% 静默兜底（via=fallback、约 1 秒返回），
单参数的 `knowledge_base_qa` 正常。

**根因**：DeepSeek 对多参数工具输出的 Action Input 是 JSON **字符串**
（`{"amount": 100, "currency": "USD"}`），而 `langchain_classic` 的
`ReActSingleInputOutputParser` **不做 json.loads**，把整串原样作为单参数字符串传入，
pydantic 校验失败（amount 无法解析、currency 缺失），异常被 `smart_answer` 的
except 吞掉后静默降级为兜底回答——**表面看像"模型不会用工具"，实为解析层协议错配**。

**修复**（`src/agent.py`、`src/prompts.py`）：
1. 新增 `JSONTolerantReActParser` 继承经典解析器，对 `{...}` 形式的 Action Input
   尝试 `json.loads` 转 dict，失败再回退字符串；
2. ReAct 提示词新增规则 5：多参数工具 Action Input 必须单行紧凑 JSON，并给出
   汇率/翻译/税费三个范例；
3. `AgentExecutor(handle_parsing_errors=True, max_iterations=4)`，
   异常不再静默，错误写入 `res["agent_error"]` 可观测。修复后全工具在线复测 8/8 通过。

## 六、可信口径与简历建议

- 可写：**"同一批 60 条盲测用例，纯大模型基线下 30% 行为可用（65% 知识库问题拒答、19% 作答含编造数字、工具题 0/8），RAG+Agent 在线人工复核 93.3%、自动断言 80%；业务工具精确触发 8/8；多跳题 3/3；跨语言 2/4 且自愈不稳定，已列入 bge-m3 迭代。"**
- 不可写："准确率 100%/95%"（自动断言口径 80%，且 4 个真实失败已列出）；
  不可只写"从 11.7% 提升"（11.7% 是字符串精确匹配口径，基线应配行为口径 30% 一起解释）。
- 局限诚实清单：①断言为关键词包含而非 LLM-as-judge，空格/同义拒答造成 8 条误伤已人工修正；
  ②在线结果为单次运行快照，跨语言自愈行为已观测到不稳定性；③工具数据为内置模拟表，非真实业务 API。
