# 跨境电商客服知识库规范文档

> 对应项目交付物：知识库规范文档（素材格式 / 分类标准 / 更新流程）。
> 本规范约束原始素材采集、清洗治理、向量化入库与日常更新的全流程，
> 保证 RAG 知识库“可检索、可维护、可追溯”。

## 一、素材格式规范

### 1.1 原始素材（`data/knowledge_base_raw.xlsx`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 问题 | 文本 | 是 | 用户视角的一句话提问，≤60 字，结尾用中文问号；禁止口语脏字与测试内容 |
| 标准答案 | 文本 | 是 | 口径统一的正式话术，80-300 字；数字/时效/币种必须准确，过时内容加标【已过时】 |
| 业务分类 | 文本 | 是 | 必须取自第二章的 10 个标准分类名，不得自建/加空格 |
| 更新时间 | 日期 | 是 | `YYYY-MM-DD`；早于 2023-01-01 的政策类内容默认按过时处理 |

### 1.2 清洗后知识库（`data/knowledge_base.xlsx`）

在原始字段基础上补充：

| 新增字段 | 说明 |
|---|---|
| 适用地区 | 通用 / 美国 / 欧盟 / 日本 …，用于地域化检索与回答 |

检索文本拼接规范（向量化输入）：

```
【{业务分类}】{问题}
{标准答案}
```

## 二、业务分类标准（10 类）

| 分类 | 覆盖范围 | 典型关键词 |
|---|---|---|
| 物流配送 | 发货时效、运费、轨迹、清关、丢损件、拒收、禁运品 | 物流、快递、运费、清关、签收、运单 |
| 关税税费 | 关税/VAT/消费税/行邮税、税率、完税价格、起征点、IOSS/EORI | 关税、税费、增值税、税率、完税价格 |
| 退换货政策 | 7天无理由、换修、退款时效、运费险、价保、售后凭证 | 退货、换货、退款、售后、保修 |
| 支付方式 | 信用卡/PayPal/本地支付、预授权、拒付、分期、发票收据 | 支付、信用卡、paypal、扣款、账单 |
| 商品信息 | 尺寸材质、电压插头、认证、库存、保质期、产地、说明书 | 尺码、材质、电压、库存、正品、认证 |
| 订单查询 | 下单/取消/改单、订单状态、拆单、限购、风控审核 | 订单、取消订单、单号、订单状态 |
| 账号问题 | 注册登录、密码、绑定、2FA、封禁、隐私数据、会员等级 | 账号、登录、密码、验证码、注销 |
| 合规要求 | 禁售限售、CE/FCC/RoHS/GPSR、知识产权、申报、广告法极限词 | 合规、认证、侵权、申报、文案 |
| 活动规则 | 优惠券、满减、秒杀、预售定金、拼团、积分、价保 | 优惠、优惠券、满减、秒杀、定金 |
| 常见问题 | 客服渠道、语言币种、新手流程、礼品卡、APP 使用 | 客服、人工、营业时间、发票 |

分类歧义时按“**用户核心意图**”归类，并在 `src/config.py` 的 `CATEGORY_KEYWORDS`
中维护关键词；一条问答只归属一个主分类，不重复入库。

## 三、清洗治理规则（567 → 519）

治理管线见 `src/data_pipeline.py`，四步顺序执行并输出审计报告
（`data/cleaning_report.json`）：

1. **无效内容剔除**
   - 测试数据（问题/答案含“测试、test、请忽略、N/A”）；
   - 空答案、问题少于 6 个字符的无意义记录；
   - 标注【已过时】/【已废止】/【已停用】的旧政策；
   - 业务分类不在 10 个标准分类内的记录。
2. **去重合并**
   - 原文完全一致 → 精确去重；
   - 仅标点全半角/语气符号/空白不同 → 归一化（去空白与标点、统一问号、转小写）后合并，答案保留口径更完整的一条。
3. **标准化处理**
   - 问题去多余空白、统一中文标点；去除答案“答：”前缀；
   - 分类名 trim；按问题内容自动标注适用地区。
4. **复核入库**
   - 去重后按分类清点数量（9 类 ×52 条 + 订单查询 51 条 = 519）；
   - 落盘 `knowledge_base.xlsx` 后才允许构建向量索引。

## 四、切分与向量化规范

- 切分器：`RecursiveCharacterTextSplitter`，`chunk_size=500`、`chunk_overlap=50`，
  分隔符优先级 `换行 → 。→ ；→ ！→ ？→ ，→ 空格`，保证语义完整；
- 嵌入模型：`BAAI/bge-small-zh-v1.5`（512 维，向量 L2 归一化，CPU 推理）；
- 每个 chunk 必须携带元数据 `category / question / region / updated`，
  切分时随文档继承，用于分类过滤、重排加权与结果溯源；
- 索引持久化目录：`faiss_index/`（`index.faiss` + `index.pkl`），随知识库版本整体重建。

## 五、知识库更新流程

```
业务变更（政策/时效/活动）
      │
      ▼
运营提交新素材（符合第一章格式）→ 放入原始采集表
      │
      ▼
执行 prepare_data.py 全量治理 → 核对 cleaning_report.json 中的剔除/合并明细
      │
      ▼
执行 build_index.py 重建 FAISS 索引（新版本全量替换，不做增量混用）
      │
      ▼
执行 run_eval.py 回归 60 条分层用例（8 题开发回归 + 52 题独立盲测）
      → 准确率不低于上一版本、且不新增应拒答组失败，方可上线
      │
      ▼
Badcase 入池：新失败用例补充进 eval_cases.py，进入下一轮迭代
```

更新纪律：

- **时效性**：税费、物流时效、活动规则每季度复核一次；各国政策突变时即时更新；
- **可追溯**：每条素材保留更新时间；过时内容不得直接删除语义不清的版本，需用新口径替换；
- **不超纲**：与跨境电商业务无关或无法证实的内容不得入库，宁可由系统触发兜底拒答；
- **评测前置**：任何知识库版本上线前必须通过 `run_eval.py` 全量回归并留存报告；
- **开发集/盲测集隔离**：阈值、同义词、重排权重只能依据开发回归集调整；盲测题在系统冻结后一次性运行，
  失败用例只记录、进入下一迭代 backlog，禁止为了让盲测分数好看而针对性回改（防止评测过拟合）。
