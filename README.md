# 跨境电商 RAG 智能问答 Agent

基于 **LangChain** 搭建的「知识库检索增强（RAG）+ ReAct Agent 工具调用」智能客服系统，
覆盖物流、关税、退换货、支付等 **10 类跨境电商核心咨询场景**，
通过结构化知识库、三段式增强检索与置信度兜底有效抑制大模型幻觉。

> 项目与简历/设计文档完全对齐：567 条原始素材 → 519 条高质量知识库、
> 三段式增强检索、5 类业务工具、60 条分层盲测用例（开发集/盲测集隔离）、4 轮迭代评测体系，
> 并已用真实 DeepSeek API 完成在线实测（纯 LLM 基线 → RAG+Agent，同一批 60 题）。

---

        │ ③ 关键词重排 bigram覆盖+分类加权      │            └──────────────────┬──────────────────┘

- **嵌入模型**：`BAAI/bge-small-zh-v1.5`（512 维，CPU 可跑，完全离线；约 95MB）
- **向量库**：FAISS 本地索引，无需任何外部服务
- **大模型**：DeepSeek（OpenAI 兼容协议，可替换通义/智谱等）；**未配置密钥时自动进入离线演示模式**，全链路仍可运行与评测
- **Agent**：LangChain 1.x 的 `langchain_classic.create_react_agent` + `AgentExecutor`（ReAct 推理）

## 三、快速开始

### 1. 安装依赖（Python 3.10+）

```bash
python -m venv rag_env
rag_env\Scripts\activate          # Windows
# source rag_env/bin/activate     # Mac/Linux
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 2. 配置大模型密钥（可选，不配也能离线运行）

```bash
copy .env.example .env            # 填入 DEEPSEEK_API_KEY
```

嵌入模型默认走本地 BGE，无需密钥。首次构建索引会自动下载 bge-small-zh-v1.5
（已设置 `HF_ENDPOINT=https://hf-mirror.com` 镜像，国内可直连）。

### 3. 一键构建知识库与索引

```bash
python prepare_data.py    # 567 条原始素材 → 清洗 → 519 条知识库
python build_index.py     # 递归切分 → BGE 向量化 → FAISS 落盘
```

### 4. 启动问答

```bash
python app.py
```

示例（离线模式即可体验）：

```
我：美国包裹一般多久能到？
我：100美元等于多少人民币
我：检测这句文案：“全网第一限时秒杀，百分百好评”
我：500元的香水要交多少税
我：帮我把“感谢您的购买”翻译成英文
我：帮我查一下订单 CB20261023A88
我：今天天气怎么样？          → 触发兜底拒答
```

输入 `/debug` 可查看粗筛分类、置信度和 Top-K 检索轨迹。

### 5. 自动化评测

```bash
python run_eval.py                 # 离线三轮迭代对比，生成 eval/report_*.md
python run_online_eval.py          # 配置 DeepSeek 后在线实测：基线60 + Agent60 + 温度消融
```

也可用 promptfoo 复核断言（需 Node.js 18+）：

```bash
cd eval
npx promptfoo@latest eval
```

## 四、核心实现说明

### 三段式增强检索（`src/retriever.py`）

1. **主题粗筛**：10 类业务关键词表匹配分类，分类内定向召回并加权（同时合并全库召回，避免误分类漏召回）；
2. **语义召回**：FAISS Top-10，归一化向量的 L2 距离换算为 [0,1] 相似度；
3. **关键词加权重排**：无分词依赖的中文 bigram 覆盖率（0.75）+ 单字平滑（0.25），
   叠加口语同义词扩展（如“快递→物流、几天→时效、付不了→拒绝/失败”），
   `final = 0.7*语义 + 0.3*关键词 + 0.05*分类加权`；
4. **置信度兜底**：最高分 < `SCORE_THRESHOLD=0.60` 时返回统一拒答话术。

### 5 类业务工具（`src/tools.py`）

| 工具 | 能力 | 实现方式 |
|---|---|---|
| `exchange_rate_calculator` | 8 种主流币种与人民币双向换算 | 内置基准汇率 |
| `content_compliance_check` | 广告法极限词/虚假承诺/医疗宣称检测 | 三级风险词库匹配 |
| `translator` | 中英日客服翻译 | 在线走大模型 / 离线内置高频短句库 |
| `order_delivery_query` | 订单物流节点与时效查询 | 订单号规则模拟（稳定哈希） |
| `tax_estimator` | 跨境综合税估算 | 品类税率表 + 各国免税额规则 |

### 离线演示模式

未配置 `DEEPSEEK_API_KEY` 时：RAG 回答降级为 Top-1 标准知识条目抽取、
工具由轻量意图识别直接路由执行。这样**检索、工具、评测、拒答全链路零密钥可复现**；
配置密钥后自动切换为 DeepSeek 生成式回答与 ReAct Agent，无需改任何代码。

## 五、评测与迭代（对应文档第七章）

### 5.1 用例设计：开发集 / 盲测集隔离（避免“题库即考卷”）

| 集合 | 规模 | 用途 |
|---|---|---|
| 开发回归集 | 20 条（eval_cases.py 中 #1-8 直问 + #17-20 等典型题） | 第 1-3 轮迭代调参的唯一依据 |
| **独立盲测集** | **60 条分层全集**（8 题直问回归 + 52 题独立设计） | 系统冻结后一次性运行，**不允许据其回改代码** |

60 条覆盖 9 类高压场景：常规 16 / 模糊口语 10 / 跨工具 8 / 超纲拒答 6 / 边界异常 6 /
**对抗注入 5**（提示词注入、越狱、隐私索取、虚假前提）/ **跨语言 4**（英/日文提问）/
**多跳组合 3**（需整合两条知识）/ 否定约束 2。断言全部取自知识库与工具真实输出的可核验 token。

### 5.2 本机离线实测结果（60 条盲测，系统冻结）

| 版本 | 总准确率 | 应拒答组（17题） | 应答组（43题） | 主要发现 |
|---|---|---|---|---|
| 第1轮 纯向量（阈值0.55） | 85.0% | 82.4% | 86.0% | 松阈值导致钓鱼邮件/隐私索取被强行作答（安全事故） |
| 第2轮 三段式检索 | 81.7% | 94.1% | 76.7% | 安全性提升，但口语题召回下降 |
| 第4轮 最终冻结版 | **83.3%** | **94.1%** | 79.1% | 常规/工具/拒答/边界均 100%，短板集中在跨语言与多跳 |

最终轮 10 个真实 Badcase（检索层 8 + 生成层 2）：跨语言 4 条全挂（bge-small-zh 对英/日文语义漂移）、
多跳 2 条（两条知识都已召回，但离线 Top1 抽取不会整合——在线 LLM 基于 Top3 可解）、
临界口语/否定 3 条（得分 0.45-0.60 落在阈值附近）、对抗纠偏 1 条（带噪声陈述干扰召回）。
逐条证据（Top3 得分、系统回答）见 `eval/report_*.md/.xlsx`，下一轮对策：bge-m3 多语种嵌入、
查询改写扩召回、多片段答案合成。

**双框架交叉验证**：同一批 60 题用 promptfoo（Node 侧独立 Provider）复跑，结果同为 50/60 = 83.3%，
且 10 个失败用例与 Python 评测完全一致（`eval/promptfoo_result.json`）。

### 5.3 真实 API 在线实测（同一批 60 题，DeepSeek deepseek-chat，20261023）

| 版本 | 自动断言（关键词精确匹配） | 人工语义复核 | 备注 |
|---|---|---|---|
| 第0轮 纯大模型（无知识库/工具） | 11.7% | **30.0%** | 知识库内问题 65% 被谨慎回避、19% 作答含编造数字（如美国时效编造3-7/7-15/15-30天，知识库口径7-12天）、工具题 0/8 |
| 离线第4轮 检索+Top1抽取 | 83.3% | 83.3% | 10 个失败经轨迹核验全部真实 |
| **在线第4轮 RAG+ReAct Agent** | **80.0%** | **93.3%** | 8 条断言误伤（数字两侧空格、同义拒答措辞），4 条真实失败 |

在线实测的关键发现（明细见 `eval/online_report_20261023_225018.md` 与 `online_eval_*.xlsx`）：

- **业务工具 8/8 精确触发无错调**（knowledge_base_qa 触发 44 次，5 类业务工具仅在对应题触发），平均 4.8s/题；
- **多跳题 3/3**：离线 Top1 抽取无法整合的问题，在线 LLM 基于 Top3 上下文综合作答；
- **对抗注入 5/5 行为正确**（拒绝提示词注入/钓鱼邮件/隐私索取/私下交易，其中 4 条因自由措辞不匹配固定断言句被自动口径误判，人工复核通过）；
- **4 个真实失败**：临界口语 #24、虚假前提纠偏 #49、跨语言 #53/#55——与离线短板重合，未做针对性粉饰；
- **跨语言"自愈"不稳定**：#52/#54 英文业务题 Agent 多数轮次自主改写中文检索通过（批量+复测 6/7），
  但 #53 术语题、#55 日文题 4 次复现全挂 → bge-m3/显式查询翻译仍是必须做的 backlog，不能依赖 Agent 涌现；
- **temperature 消融**：同一份检索上下文下 0/0.1/0.3 事实断言均 100%、平均字数 95/85/86——
  检索命中时温度只影响措辞不影响事实性，生产取 0.1；真正的幻觉风险靠阈值兜底而非调零温度。
- **联调修复的真实 Bug**：DeepSeek 对多参数工具的 Action Input 输出 JSON 字符串，
  `langchain_classic` 经典解析器不做 `json.loads` 导致 pydantic 校验失败、静默兜底；
  已用 `JSONTolerantReActParser`（`src/agent.py`）+ 提示词紧凑 JSON 范例修复。

> 为什么不展示 100%？20 条开发集上最终版曾为 100%，但那只说明拟合了开发分布；
> 60 条盲测才暴露跨语言、多跳等真实短板，在线真实 API 复测后仍保留 4 个真实失败。
> **刻意把失败修干净再跑测试没有工程意义。** 第0轮基线已用真实 API 实测，
> 系统不产生任何虚构数字；简历口径："纯 LLM 基线 30% 行为可用 → RAG+Agent 在线复核 93.3%（自动断言 80%）"，
> 必须同时说明断言口径与剩余短板。

Badcase 按文档口径三层归因：**检索层**（切分/召回/重排/跨语言漂移）、**生成层**（多片段整合/temperature）、
**数据层**（知识库缺口/拒答标注）。

## 六、常见问题与排错

1. **FAISS 加载报错**：确认 `faiss-cpu` 版本与已保存索引匹配，删除 `faiss_index/` 重新 `python build_index.py`；
2. **BGE 模型下载慢**：已内置 hf-mirror 镜像；也可手动下载 `BAAI/bge-small-zh-v1.5` 后在 `.env` 设置 `BGE_MODEL=本地路径`；
3. **大模型调用超时**：`config.py` 已设置 30s 超时与 2 次重试，请检查密钥与网络；
4. **幻觉仍然出现**：检查 `/debug` 输出的检索片段是否命中、降低 `LLM_TEMPERATURE` 至 0.1、强化拒答阈值；
5. **检索不准**：用 `calibrate_retrieval.py` 观察得分分布，调整 chunk 大小、分类关键词、重排权重与阈值。
